# Angular 相依套件升級至 20.3.25 並重新 build 交付產物

本次工作為相依套件的維護性升級：將 `package.json` 內 `@angular/*` 的 semver 範圍由 `^20.3.17` / `^20.3.18` 提升至 `^20.3.25`，重新安裝取得新的 `package-lock.json`，並執行 `npm run build` 產生新的 `src/main/resources/static/dgrv4/ac4/` 交付產物。**不涉及任何 Angular 原始碼（`src/app/**`）異動**。

## 修改內容

### 問題描述

- `package.json` 宣告的 `@angular/*` 版本範圍停留在 `^20.3.17` / `^20.3.18`，與上游已釋出的 patch 版本落差逐漸拉大。
- 相依樹中多個傳遞相依（`brace-expansion`、`selfsigned`、`ws`、`undici`、`tar`、`http-proxy-middleware` 等）也需要一併刷新至較新的 patch/minor 版本。
- 依 `.claude/rules/commit-pr.md` 的「Angular Build 與上傳規範」，本次同時要求 build 與上傳，因此 `static/dgrv4/ac4/` 的 build 產物必須併入本次提交。

## 預計修改方式

**Context** — 需求為「升級 Angular 相依並重新 build，之後建立工作日誌並上傳到 `develop`」。

**分析**

- 本專案的 Angular `outputPath` 指向後端 tracked 的 `../src/main/resources/static/dgrv4/ac4/`（見 `angular.json`），並非一般不應提交的 `dist/`；依 `.claude/rules/commit-pr.md` 的「Angular Build 與上傳規範」，使用者同時要求 build 與上傳時，產物必須併入提交。
- 升級只動 `package.json` 的 semver 範圍與 lock，不改動 `src/app/**`；因此不需要 i18n、元件或 API 層的配套修改。
- `git status` 顯示本地 `develop` 與 `eapdd2025/develop` 同步，工作區的差異全部來自本次升級與 build。

**修正方案** — 提升 `@angular/*` 至 `^20.3.25` → 重新安裝更新 lock → `npm run build` 產生產物 → 建立本工作日誌 → 將 `package.json`、`package-lock.json`、`static/dgrv4/ac4/` 產物與本文件一併 commit 並推送至 `eapdd2025/develop`。

### 經驗紀錄（給未來類似任務參考）

- **只看 `package.json` diff 會低估升級範圍**：本次 `package.json` 只動了 9 行，但 lock 實際有 108 個套件版本異動、且含 `selfsigned` 這種 major 升版與 `node-forge` 被整組替換。要如實描述升級影響，必須比對 `git show HEAD:...package-lock.json` 與現行 lock 的 `packages` 版本，而非只看宣告的範圍。
- **caret 範圍會連帶更新未宣告調整的套件**：`@angular-devkit/build-angular` / `@angular/cli` 的宣告仍是 `^20.3.20`，但實際安裝由 `20.3.25` 跳到 `20.3.32`。升級後應確認建置工具鏈的實際版本，而不是假設「沒改宣告就沒變」。
- **`package.json` 範圍與 lock 版本不會完全相等**：宣告 `^20.3.25`、實際安裝 `20.3.26` 是 caret 的正常行為，記錄時要標明兩者差異，避免日後誤判 lock 不同步。
- **chunk 編號重算屬正常現象**：升級建置工具鏈後 lazy chunk id 可能重新分配（本次 `9286` → `7676`），不代表模組內容變更；日誌中應標註，避免 review 時被誤認為功能異動。
- 本專案的 build outputPath 是後端 tracked 的 static 目錄，「build 且上傳」時必須把 `index.html`、新 hash bundles 與被取代的舊 bundles 一併提交（見 [`2026-07-16_agent-build-upload-artifact-rule.md`](./2026-07-16_agent-build-upload-artifact-rule.md)）。
