### 詳細程式碼異動

#### 1. 新增忽略 1298 的 AA0320 service 方法

修改前僅有一般 `npPost()` 呼叫：

```ts
queryGroupApiList(ReqBody: AA0320Req): Observable<ResAA0320> {
  // request body 組裝略
  return this.api.npPost<ResAA0320>(path, body);
}
```

修改後保留原方法，另增專供需要忽略 `1298` 情境使用的方法：

```ts
queryGroupApiList_ignore1298(ReqBody: AA0320Req): Observable<ResAA0320> {
  return this.api.excuteNpPost_ignore1298<ResAA0320>(
    `${this.npBasePath}/AA0320`,
    {
      ReqHeader: this.api.getReqHeader(TxID.queryGroupApiList),
      ReqBody,
    } as ReqAA0321,
  );
}
```

#### 2. AC0301 詳細清單改用 ignore1298 方法

修改前：

```ts
this.apiService.queryGroupApiList(ReqBody).subscribe((res) => {
  // response handling
});
```

修改後：

```ts
this.apiService.queryGroupApiList_ignore1298(ReqBody).subscribe((res) => {
  // response handling
});
```

最終依使用者釐清，只有詳細清單首次載入與關鍵字重新查詢使用 `_ignore1298`；帶 `gId` 的「查看更多」維持一般方法：

```ts
this.apiService.queryGroupApiList(ReqBody).subscribe((res) => {
  // 查無更多資料時保留既有彈窗處理

```

## 預計修改方式

### 需求：AC0301 詳細清單的 AA0320 忽略 1298

**Context** — 使用者指出 AC0301 詳細清單會呼叫 `AA0320`，要求改用專案慣例中的 `xxxx_ignore1298` 方法。

**分析** — 搜尋 repository 後確認，`ApiService.queryGroupApiList()` 原本透過 `ApiBaseService.npPost()` 呼叫 `AA0320`；`ApiBaseService` 已有 `excuteNpPost_ignore1298()`，而其他 API service 也普遍以 `_ignore1298` 後綴包裝。另確認 `queryGroupApiList()` 不只由 AC0301 使用，`np01/np1202/api-detail-content` 仍有一般呼叫需求，因此不能直接改名或全面改變原方法行為。

**修正方案** — 保留 `queryGroupApiList()`，另增 `queryGroupApiList_ignore1298()`；AC0301 詳細清單首次載入與關鍵字查詢切換至新方法，「查看更多」則維持原方法，以保留查無更多資料時的彈窗提示。NP1202 同樣維持原本的一般錯誤處理行為。

### 需求：build、工作日誌與上傳

**Context** — 使用者明確要求執行 `npm run build`，成功後建立工作日誌並一併上傳。

**分析** — 專案規範指出此情境須保留並提交 `../src/main/resources/static/dgrv4/ac4/` 的 `index.html`、新 hash bundles 與被取代的舊 bundles。工作樹另有 `application.properties`、`.claude/settings.local.json` 與 `srcVite/` 等既有無關變更，不應納入本次提交。

**修正方案** — 正式 build 成功後建立本文件；提交時只納入兩個程式檔、本文件，以及本次 build 造成的 static bundle 汰換，不暫存既有無關變更。

### 經驗紀錄（給未來類似任務參考）

- 共用 service 方法改名或改變錯誤處理前，必須全站搜尋呼叫端；即使需求只點名單一畫面，也不能假設方法只供該畫面使用。
- `_ignore1298` 是特定呼叫情境的行為差異。保留一般方法並新增明確後綴的方法，可避免其他功能被動改變錯誤提示策略。
- 詳細清單的 AA0320 不只在進入明細時呼叫，也包含關鍵字查詢及「查看更多」續查；不同呼叫點可能需要不同錯誤提示策略，不能僅因交易代碼相同就全面替換。
- build 成功後若又補改任何 runtime code，先前 build 產物即不再代表最終程式碼，必須重新 build。
- 工作樹有既有未提交內容時，應先記錄 build 前狀態，再以明確路徑暫存，避免將無關檔案混入上傳。
